# プルリクエスト（PR）規約

## 基本方針

- `main` への変更は必ず PR を経由する（直接 push は禁止）。
- PR の base は `main`、head は作業ブランチ（[ブランチ命名規約](./branch.md) 参照）。

## タイトル

- **英語**・[Conventional Commits](./commit.md) の形式に合わせる（例: `feat: add TODO creation endpoint`）。
- Squash マージ時、このタイトルが main のコミット件名になる。簡潔に書く。

## 説明（body）

- `.github/pull_request_template.md` の雛形に従う。
- 「何を」より「なぜ」を中心に書く。
- 関連する Issue があれば参照する（例: `Closes #12`）。

## マージ戦略

- **Squash マージを標準とする**。PR の複数コミットを 1 つにまとめて main に載せる。
- main の履歴を 1 PR = 1 コミットに保ち、追いやすくする。
- リポジトリ設定で Squash 以外のマージ方式は無効化する。

## レビュー

- レビュー承認は**必須ではない**（現状は 1 人開発を想定）。
- ただし CI がある場合は green を確認してからマージする。
- 複数人開発に移行する場合は、承認必須化をブランチ保護に追加する。

## マージ後

- マージ済みの作業ブランチは削除してよい。

## ブランチ保護（main）

GitHub のブランチ保護で以下を強制する（`gh api` で設定）。

- `main` への直接 push を禁止
- force push を禁止
- 変更は PR 経由を必須とする

規約は「読ませるもの」、ブランチ保護は「守らせる仕組み」。両輪で運用する。
